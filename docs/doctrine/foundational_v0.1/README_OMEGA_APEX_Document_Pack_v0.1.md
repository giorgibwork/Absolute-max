# OMEGA APEX — Foundational Document Pack

**Pack version:** 0.1  
**Prepared:** 13 November 2026  
**Purpose:** Establish the product vision, governing Constitution and master technical architecture before implementation planning.

## Reading order

1. **OMEGA APEX Vision, Identity, Architecture and Foundational Doctrine v0.1**  
   Defines what OMEGA APEX should be, its mission, core principles, architectural planes, subsystem charters, quality expectations and maturity model.

2. **OMEGA APEX Supreme Constitution v1.0-draft**  
   Defines governing authority, instruction hierarchy, PREPARE_ONLY autonomy, approvals, mission integrity, model governance, evidence, resource rules and amendment procedure. This is a proposed draft and is not ratified until the human operator explicitly accepts it.

3. **OMEGA APEX Master Technical Architecture Specification v0.1**  
   Translates the vision and proposed Constitution into subsystem boundaries, contracts, state machines, data models, interfaces, routing, memory, capability governance, resource accounting, verification, recovery and acceptance criteria. It is not a build guide and does not authorize changes to DSH.

## Governing decisions captured

- Purpose: hybrid personal intelligence system and AI workforce.
- Constitutional priority: absolute within OMEGA, subject to external host, legal and provider requirements.
- Autonomy: PREPARE_ONLY.
- Optimization: all meaningful performance dimensions, with constitutional and authorization requirements as hard gates.
- Initial AI subscription ceiling: USD 10/month unless explicitly revised by the human operator.
- Initial host: DSH Go on Android; host portability remains a design objective.

## Status discipline

The vision document is a foundational conceptual doctrine. The Constitution is a proposed draft, not ratified. The technical architecture is a design proposal, not implemented software. Any DSH audit observations are historical and must be revalidated before implementation decisions.

No document in this pack authorizes software installation, configuration changes, credential generation, subscription purchases, external account creation or infrastructure deployment.

## Versioning rule

The documents should be revised independently:

- Constitution revisions require explicit human ratification.
- Technical architecture revisions require a recorded design decision and compatibility review.
- Vision revisions require a reasoned review of product identity and foundational priorities.

Every revision should preserve its predecessor and identify the changes made.
